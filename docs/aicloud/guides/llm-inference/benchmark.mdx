# LLM 基准测试

LLM 基准测试用于向运行中的模型部署持续发送请求，观察吞吐、延迟和错误率，适合验证模型部署是否稳定、比较不同资源规格，或在上线前估算服务容量。

平台当前使用 GuideLLM 执行压测，请求接口固定为 OpenAI 兼容的 `/v1/chat/completions`，压测模式固定为恒定请求速率（`constant`）。

:::caution
基准测试会产生真实推理流量并占用 GPU、CPU 和网络资源。建议先在非生产部署上从较低请求速率开始，确认服务稳定后再逐步提高压力。
:::

## 快速开始 {#quickstart}

一次基础测试的流程如下：

```text
准备运行中的模型部署
  -> 创建基准测试
  -> 等待测试完成
  -> 查看 QPS、延迟和错误率
  -> 按需查看日志或下载报告
```

### 1. 准备模型部署

进入控制台 **人工智能 → 推理 → 模型部署**，确认目标部署已经可以正常提供推理服务。

基准测试创建页只会列出满足以下任一条件的部署：

- 已有就绪副本；
- 已有运行中的推理实例。

如果下拉框中没有目标部署，请先检查部署状态、模型加载日志、GPU 资源和服务连接信息。Ollama 部署可参考 [Ollama](./ollama)；vLLM、SGLang 等后端也需要先确保模型部署已正常运行。

平台还需要存在类型为 `benchmark` 的 GuideLLM 镜像。社区镜像列表见 [llmimages.yaml](https://www.cloudpods.org/llmimages.yaml)。该镜像通常由管理员预先导入，普通用户创建测试时不需要手动选择。

### 2. 创建基准测试

进入 **人工智能 → 推理 → 基准测试**，点击 **新建**，填写测试名称并选择模型部署。

> **图片占位：基准测试列表页**
>
> 后续替换为包含“新建”、名称搜索、模型部署筛选和状态筛选的完整列表页截图。

选择部署后，如果名称仍为空，页面会自动生成以 `bench-` 开头的名称。建议在名称中体现模型、资源规格或测试目的，例如：

```text
bench-qwen3-8b-1gpu
bench-qwen3-8b-rate4
```

基础测试使用平台生成的 `synthetic_text` 数据集。创建页参数如下：

> **图片占位：创建基准测试表单**
>
> 后续替换为包含模型部署、请求速率、总请求数、最大测试时长、最大错误数和 Token 数的创建页截图。

| 页面字段 | 默认值 | 作用与填写建议 |
| --- | ---: | --- |
| 请求速率 | `1` | 每秒计划发起的请求数。值越大，对模型部署施加的并发压力越高；支持小数，最小为 `0.1`。 |
| 总请求数 | `100` | 本次测试最多发送的请求数，达到该数量后结束。 |
| 最大测试时长（秒） | `600` | 测试允许运行的最长时间，避免长时间占用测试运行器。 |
| 最大错误数 | `10` | 失败请求达到该数量时提前停止；可设为 `0`，表示出现首个错误即停止。 |
| 输入 Token 数 | `1024` | 生成测试 Prompt 的近似输入长度，用于模拟不同上下文长度。 |
| 输出 Token 数 | `128` | 期望模型生成的近似输出长度，用于模拟不同生成长度。 |

填写完成后点击 **创建**。创建成功后，页面会返回基准测试列表，并打开本次测试的详情面板。

:::tip
首次压测建议保留默认值。确认测试可以正常完成后，再逐步提高请求速率或 Token 数；一次只调整一个主要变量，结果更容易比较。
:::

### 3. 等待测试完成

列表会自动刷新处于运行阶段的测试。常见状态如下：

| 状态 | 含义 |
| --- | --- |
| 等待中 | 测试任务已经创建，正在等待调度。 |
| 排队中 | 测试运行器正在排队等待执行。 |
| 运行中 | 正在向模型部署发送请求。 |
| 已完成 | 测试正常结束，结果和报告已经生成。 |
| 已停止 | 用户主动停止，或测试清理完成后进入停止状态。 |
| 错误 | 目标服务、运行器或测试参数发生错误。 |

列表支持按名称、模型部署和状态筛选，并显示请求速率、计划请求数、已发送请求、成功请求、失败请求、错误率、平均 QPS 和平均延迟。

### 4. 查看测试结果

点击测试名称打开详情面板。详情主要分为以下几部分：

> **图片占位：基准测试详情面板**
>
> 后续替换为同时展示概览、压测参数和压测结果的详情截图。

- **概览**：状态、状态说明、模型部署、推理后端、模型和目标地址；
- **压测参数**：请求速率、总请求数、最大时长、最大错误数和 Token 数；
- **压测结果**：平均 QPS、平均延迟、已发送请求、成功请求、失败请求和错误率；
- **调试信息**：目标快照、GuideLLM 配置、原始指标、日志和报告。

常用指标可这样理解：

| 指标 | 含义 |
| --- | --- |
| 平均 QPS | 测试期间平均每秒完成的请求数。 |
| 平均延迟 | 单个请求从发送到完成的平均耗时。 |
| 成功请求 | 获得有效响应的请求数。 |
| 失败请求 | 请求超时、连接失败或服务返回错误的请求数。 |
| 错误率 | 失败请求占已发送请求的比例。 |

请求速率是压测器计划施加的负载，不保证实际 QPS 一定达到相同数值。当模型处理速度不足、请求排队或发生错误时，实际 QPS 可能更低，平均延迟也会升高。

## 设计一组可比较的测试

比较两个结果时，应尽量保持以下条件一致：

- 模型和模型版本；
- 推理后端及其启动参数；
- GPU 型号、GPU 数量、CPU 和内存；
- 输入 Token 数和输出 Token 数；
- 请求速率、总请求数和最大时长；
- 测试期间部署上是否还有其他业务流量。

推荐按下面顺序逐步增加压力：

1. 使用默认请求速率 `1` 验证测试闭环。
2. 依次使用 `2`、`4`、`8` 等请求速率重复测试。
3. 观察平均 QPS 是否继续增长，以及平均延迟和错误率何时明显上升。
4. 找到满足业务延迟和错误率要求的最高稳定负载。

如果要评估长上下文能力，可以单独提高输入 Token 数；如果要评估持续生成能力，可以单独提高输出 Token 数。不要同时修改多个变量，否则很难判断结果变化来自哪里。

## 停止、删除和报告

### 停止运行中的测试

在等待中、排队中或运行中的测试右侧点击 **停止压测**，确认后平台会请求停止并清理测试运行器。

停止并非瞬间完成，列表可能短暂保留原状态；请等待状态最终变为 **已停止**。停止后的测试不能从中断位置继续运行，如需再次执行，请新建测试；支持“重新测试”的版本也可以按后文说明重新执行。

### 查看日志和下载报告

测试进入已完成、已停止或错误状态后，可以在详情面板的 **报告与日志** 区域，或列表行的 **更多** 菜单中使用以下操作：

> **图片占位：报告与日志操作**
>
> 后续替换为包含查看日志、下载日志、下载 JSON 报告和下载 CSV 报告入口的截图。

- **查看日志**：在弹窗中查看 GuideLLM 执行日志；
- **下载日志**：下载 `guidellm.log`；
- **下载 JSON 报告**：下载 `benchmarks.json`，适合查看完整请求、响应和原始统计；
- **下载 CSV 报告**：下载 `benchmarks.csv`，适合用表格工具继续分析。

如果下载入口尚不可用，通常表示测试仍在运行、对应文件尚未生成，或测试在生成该文件前已经失败。

### 删除测试

删除前应先停止仍在运行阶段的测试，并等待其进入终态。删除会清理当前测试及其结果文件，请先下载需要保留的日志和报告。

## 高级数据集与重复测试

### 从 Hugging Face 导入数据集

在支持该功能的版本中，点击新建按钮旁的下拉菜单，选择 **从 Hugging Face 导入**。填写数据集仓库、Revision、JSONL 文件路径和目标模型部署后，平台会：

> **图片占位：从 Hugging Face 导入数据集**
>
> 后续替换为包含仓库、Revision、JSONL 文件、标准答案列和基准测试参数的导入表单截图。

```text
下载 JSONL 数据集
  -> 封装并保存数据集 Package
  -> 创建基准测试
  -> 最多抽取 10 条数据做预检
  -> 执行正式测试
  -> 根据标准答案生成评分结果
```

主要字段如下：

| 页面字段 | 必填 | 默认值或说明 |
| --- | ---: | --- |
| Package 名称 | 是 | 数据集在平台内的名称。 |
| Hugging Face 仓库 | 是 | 例如 `open-r1/OpenR1-Math-220k`。 |
| Revision | 否 | 默认为 `main`。 |
| JSONL 文件 | 是 | 仓库内的文件路径，例如 `data/train.jsonl`。 |
| 标准答案列 | 否 | 未填写时依次探测 `reference_answer`、`answer`、`solution`、`target`、`label`。 |
| 基准测试名称 | 是 | 本次测试的名称。 |
| 模型部署 | 是 | 接收测试请求的运行中部署。 |
| 请求速率、总请求数、最大时长、最大错误数 | 否 | 默认值与基础测试一致。 |

导入完成前，基准测试可能还不会出现在列表中。平台会在 Package 准备完成后自动创建并启动测试，不需要重复点击创建。

数据集测试会先进入 **验证中**。预检数量固定为数据集行数与 `10` 中的较小值；预检失败时不会继续执行正式测试。

### 查看数据集评分

如果平台能唯一确定标准答案列，正式测试完成后会显示评分摘要：

> **图片占位：数据集预检与评分结果**
>
> 后续替换为包含预检状态、准确率、正确数、错误数、未评分数和评分报告下载入口的详情截图。

- **已评估**：成功关联并可比较答案的请求数；
- **正确 / 错误**：确定性比较后的结果；
- **未评分**：缺少标准答案、答案格式不支持、重复 Prompt 答案冲突或请求无法关联；
- **准确率**：`正确 / (正确 + 错误)`，未评分请求不进入分母。

评分不会再次请求被测模型，也不会调用 Judge 模型。文本比较会折叠空白并忽略简单大小写差异；纯数字按精确数值比较。

支持该功能的版本还可能提供预检报告、评分 JSON、评分 CSV 和评分日志。完整请求与响应仍以 `benchmarks.json` 为准。

### 从已有测试创建

如果希望更换模型部署、比较不同资源规格，或保留旧结果后再运行一次，请使用 **从已有基准测试创建**。

新测试会复用源测试的数据集和测试镜像，并允许覆盖名称、模型部署、请求速率、总请求数、最大时长和最大错误数。源测试及其结果不会被修改。

### 修改和重新测试

只有已完成、已停止或错误状态的测试可以修改或重新测试：

- 只修改名称或描述，不会清空旧结果；
- 修改请求速率、请求数、时长、错误数或 Token 数后，旧结果立即失效；
- **重新测试** 会清理并覆盖当前结果，然后从等待中状态重新执行；
- 如果需要保留旧结果，应使用 **从已有基准测试创建**，不要使用重新测试。

| 测试状态 | 修改参数 | 重新测试 | 删除 | 停止 |
| --- | ---: | ---: | ---: | ---: |
| 等待中 / 排队中 / 验证中 / 运行中 | 不可用 | 不可用 | 不可用 | 可用 |
| 已完成 / 已停止 / 错误 | 可用 | 可用 | 可用 | 不可用 |

## 常见问题

### 创建页没有可选的模型部署

目标部署还没有就绪副本或运行实例。返回 **人工智能 → 推理 → 模型部署**，检查部署状态、模型加载日志、GPU 资源和服务地址。

### 测试长时间停留在等待中或排队中

通常与测试运行器镜像、调度资源或后台任务有关。确认平台已经导入 `benchmark` 类型的 GuideLLM 镜像，并联系管理员检查任务状态和可用计算资源。

### 测试很快进入错误状态

先查看状态说明和 GuideLLM 日志，重点检查：

- 模型部署是否仍在运行；
- 目标服务是否支持 `/v1/chat/completions`；
- 模型名称和服务地址是否有效；
- 最大错误数是否设置过小；
- 输入或输出 Token 数是否超过模型限制；
- GPU 显存不足、请求超时或服务重启。

### 平均 QPS 为什么低于请求速率

请求速率表示计划发起请求的速度，不是性能结果。模型生成速度、排队、长输出、错误重试和服务并发上限都会让实际完成 QPS 低于请求速率。

### 为什么没有数据集准确率

基础 `synthetic_text` 测试只衡量性能，不计算答案准确率。Hugging Face 数据集测试还需要唯一的标准答案列；未找到或同时匹配多个候选列时，性能测试仍会执行，但评分会被跳过。

### 为什么修改、重新测试或删除按钮不可用

测试仍处于等待中、排队中、验证中或运行中。请先停止测试，并等待状态真正变为已停止后再操作。
