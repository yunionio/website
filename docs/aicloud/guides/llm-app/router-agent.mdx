# 路由智能体

路由智能体使用一个轻量路由模型判断请求属于 `simple`（简单）还是 `complex`（复杂），再从当前 AI 网关路由的候选模型中返回最合适的模型名称。

它只负责选模型，不直接生成最终回答。实际推理请求仍由 AI 网关转发给被选中的上游模型。

```text
客户端请求
  -> AI 网关收集候选模型
  -> 路由智能体判断 simple / complex
  -> 返回一个候选模型名称
  -> AI 网关调用该模型
```

典型用法是让翻译、摘要和短问答进入成本较低的小模型，让代码、数学、长上下文和复杂推理进入能力更强的模型。

## 快速开始 {#quickstart}

配置智能路由通常分为以下几步：

1. 准备一个用于分类的路由模型。
2. 在 AI 网关路由中准备至少两个候选模型。
3. 创建路由智能体，配置简单/复杂定义和候选模型映射。
4. 使用“路由试跑”验证分类结果。
5. 在 AI 网关路由中启用外部路由并关联该智能体。
6. 通过 AI 网关发送真实请求，确认不同请求进入预期模型。

:::tip
路由模型只需要完成二分类，优先选择响应快、成本低且能稳定输出 JSON 的模型。用于处理最终请求的候选模型可以使用更强的模型。
:::

## 1. 准备路由模型和候选模型

### 路由模型

路由智能体支持两种模型来源：

| 来源 | 适用场景 | 配置方式 |
| --- | --- | --- |
| 已有模型部署 | 路由模型已经由 Cloudpods 管理 | 选择已有且正在运行的模型部署；平台自动解析服务地址和模型。 |
| 外部服务 | 使用平台外的 OpenAI-compatible 或 Ollama 服务 | 填写服务 Base URL、驱动、模型名称和 API Key。 |

选择已有模型部署时，列表只应显示已有就绪副本或运行实例的部署。如果没有可选项，请先到 **人工智能 → 推理 → 模型部署** 检查模型服务状态。

使用外部服务时，地址必须能够访问 OpenAI-compatible 接口。建议先确认下面两个接口可用：

```text
GET <base-url>/v1/models
POST <base-url>/v1/chat/completions
```

### 候选模型

目标 AI 网关路由至少需要一个可用模型；要让简单和复杂请求产生实际分流，通常需要至少两个候选模型。

例如：

```text
simple  -> Qwen3-8B-FP8
complex -> deepseek-v4-flash
```

路由智能体中填写的候选模型名称必须与 AI 网关路由实际产生的候选名称一致。建议直接从目标路由的模型列表复制，不要自行缩写或使用别名。

## 2. 创建路由智能体

进入控制台 **人工智能 → 应用 → 路由智能体**，点击 **新建**。

> **图片占位：路由智能体列表页**
>
> 后续替换为包含新建按钮、名称、路由模型、默认路由、字符上限和状态的列表页截图。

创建页主要字段如下：

> **图片占位：创建路由智能体表单**
>
> 后续替换为包含路由模型来源、模型配置、默认路由和字符上限的创建表单截图。

| 页面字段 | 默认值 | 说明 |
| --- | ---: | --- |
| 名称 | 无 | 必填，用于识别和关联智能体。 |
| 路由模型来源 | 已有模型部署 | 选择平台内模型部署或外部服务。 |
| 模型部署 | 无 | 使用已有模型部署时必填。 |
| 路由模型地址 | 无 | 使用外部服务时必填，填写 OpenAI-compatible Base URL。 |
| 驱动 | `openai` | 外部服务可选择 `openai` 或 `ollama`。 |
| 路由模型 | 自动解析或手动填写 | 外部服务模式必填。 |
| API Key | 空 | 外部服务需要认证时填写；保存后不会明文显示。 |
| 默认路由 | `complex` | 路由模型不可用或判定失败时使用。 |
| 最大请求字符数 | 自动 | 超过该值的请求不调用路由模型，直接按复杂请求处理。 |
| 最大判定输出 Token | `64` | 限制路由模型判定结果的输出长度。 |

创建成功后状态会直接变为 **就绪**，不需要等待后台任务完成。

## 3. 定义简单和复杂请求

路由智能体使用定义和样例共同指导路由模型进行分类。

> **图片占位：路由定义、样例和候选模型映射**
>
> 后续替换为包含 simple/complex 定义、样例列表和两组候选模型标签的表单截图。

### 默认定义

如果定义留空，平台使用以下默认值：

| 路由 | 默认定义 |
| --- | --- |
| `simple` | 适合翻译、摘要、短问答和格式转换。 |
| `complex` | 适合代码、数学、长上下文、复杂推理和日志分析。 |

可以按实际业务重新定义边界。例如，客服场景可以把意图识别和固定话术归为简单请求，把需要检索、多轮分析或人工升级判断的请求归为复杂请求。

### 请求样例

为两类请求分别添加少量、清晰且互不冲突的样例：

```text
simple:
  - 把 hello 翻译成中文
  - 提取这段文本中的邮箱地址
  - 用三句话概括下面的内容

complex:
  - 分析这段 Kubernetes 日志并定位根因
  - 检查这段并发代码并给出修复方案
  - 证明这个数学结论并说明推导过程
```

平台会自动去除空样例和重复样例。不要在 simple 和 complex 中放入含义相近但预期结果不同的样例，否则会降低分类稳定性。

### 候选模型映射

分别为 `simple` 和 `complex` 选择候选模型：

- **简单请求候选模型**：优先填写低延迟、低成本模型；
- **复杂请求候选模型**：优先填写推理、代码或长上下文能力更强的模型。

两组映射都可以包含多个模型。智能体只会返回当前 AI 网关请求所提供候选集合中的模型；映射中的名称与候选集合不一致时，会触发默认回退，无法达到预期分流效果。

## 4. 配置最大请求字符数

最大请求字符数用于避免把超长内容再发送给路由模型。

### 自动计算

选择 **自动** 时，平台读取路由模型 `/v1/models` 返回的上下文窗口：

```text
优先读取 max_model_len
  -> 其次读取 context_length
  -> 字符上限 = 上下文窗口 Token 数 × 3 / 4
```

如果读取失败，则按默认上下文窗口 `8192` 计算，最终字符上限为 `6144`。自动计算失败不会阻止智能体创建。

创建完成后，详情页显示的是已经计算并保存的实际字符数，而不是“自动”或 `0`。

### 手动设置

选择 **手动** 时填写正整数。完整请求内容超过该值后：

```text
不调用路由模型
  -> 直接判定为 complex
  -> 从复杂请求候选模型中选择模型
```

该限制不会截断并转发用户请求，只决定是否跳过路由模型判定。

## 5. AI 规范并扩写

创建智能体后，可以在编辑页点击 **AI 规范并扩写**，让当前路由模型优化 simple/complex 定义，并补充代表性样例。

> **图片占位：AI 规范并扩写预览**
>
> 后续替换为同时展示原始内容、扩写结果和“应用到表单”按钮的预览截图。

操作流程如下：

1. 在编辑页调整定义或样例草稿。
2. 点击 **AI 规范并扩写**。
3. 对比原内容和扩写结果。
4. 点击 **应用到表单**，把结果写入当前本地表单。
5. 再点击普通的 **保存**，才会真正更新智能体。

关闭预览、扩写失败或未点击保存时，已保存的智能体配置不会改变。

## 6. 路由试跑

在列表或详情页点击 **路由试跑**，输入一条用户消息并确认候选模型列表。

> **图片占位：路由试跑弹窗**
>
> 后续替换为包含用户消息、候选模型和选中模型结果的试跑弹窗截图。

候选模型默认由 simple 和 complex 映射合并、去重后生成，也可以临时调整。候选列表不能为空。

建议至少验证下面两类请求：

| 测试请求 | 预期结果 |
| --- | --- |
| `翻译 hello` | 返回 simple 映射中的模型。 |
| `分析这段程序的并发问题并给出修复方案` | 返回 complex 映射中的模型。 |

试跑结果只显示最终选中的模型。当前页面不会展示内部分类、置信度或判定原因。

:::tip
试跑正常只说明智能体可以在给定候选模型中完成选择。启用真实流量前，还需要在目标 AI 网关路由中配置并验证外部路由。
:::

## 7. 接入 AI 网关路由

进入 **人工智能 → AI 网关 → 路由规则**，打开目标路由的编辑页面。

> **图片占位：AI 网关路由启用外部路由**
>
> 后续替换为包含启用开关、Router URL、路径、超时时间和失败策略的路由规则编辑截图。

确认路由已经关联所需的上游模型，然后配置：

| 页面字段 | 建议值 | 说明 |
| --- | --- | --- |
| 启用外部路由 | 开启 | 允许 AI 网关在选择上游模型前调用路由智能体。 |
| Router URL | 智能体对应的内部服务地址 | 必须是 AI 网关可以访问的地址。 |
| 路由路径 | `/route` | 路由智能体的路由入口。 |
| 超时时间 | `3` 秒 | 路由智能体的最大等待时间。 |
| 失败策略 | `priority` | 智能体超时、报错或返回无效模型时，按路由优先级回退。 |

Router URL 使用的是 LLM 服务内部地址与智能体 ID，不是控制台的 `/api/v2` 地址。该服务间接口不要求用户登录认证，应只在可信内网开放，不要直接暴露到公网。

地址格式如下，AI 网关会在其后追加路由路径 `/route`：

```text
http://<llm-service>/llm_router_agents/<agent-id>
```

完整调用过程如下：

```text
客户端调用 AI 网关
  -> AI 网关匹配路由规则
  -> 收集路由中的可用候选模型
  -> 调用路由智能体
  -> 智能体返回候选模型名称
  -> AI 网关校验返回值
  -> 调用对应上游模型
```

配置完成后，通过 AI 网关分别发送简单和复杂请求，并结合上游调用日志确认实际命中的模型。

## 编辑和删除注意事项

### 修改路由模型

修改模型部署、外部服务地址或模型名称后，字符上限不会自动重新计算。如果希望按新模型上下文窗口更新，请同时选择 **按新模型重新计算**。

### 修改 API Key

API Key 保存后不会明文显示：

- 编辑时保持密码框为空，表示不修改现有 Key；
- 需要替换时填写新的 Key；
- 需要删除时使用页面提供的清空操作。

### 删除智能体

更新智能体不会改变 ID。删除并重新创建后会生成新的 ID，所有引用旧智能体的 AI 网关路由都需要同步更新 Router URL。

删除前建议先在 AI 网关路由中关闭外部路由，或切换到其他可用智能体，避免业务请求持续触发回退。

## 回退行为

路由过程可能发生两层回退：

1. **智能体内部回退**：路由模型调用失败、输出无法解析或判定不可靠时，使用智能体的默认路由，默认是 `complex`。
2. **AI 网关回退**：智能体超时、报错或返回候选范围外的模型时，使用 AI 网关路由配置的失败策略；推荐默认使用 `priority`。

即使配置了回退，也应持续关注路由智能体的错误和超时情况。长期依赖回退会让智能分流失去作用，并可能把大量请求集中到高成本模型。

## 常见问题

### 创建页没有可选的模型部署

目标模型部署没有就绪副本或运行实例。先检查部署状态、模型加载日志和服务连接信息。

### 自动字符上限为什么是 6144

平台没有从 `/v1/models` 获取到目标模型的 `max_model_len` 或 `context_length`，因此使用默认上下文窗口 `8192`，再按 `3/4` 换算为 `6144` 个字符。

### 简单和复杂请求总是进入同一个模型

重点检查：

- simple 和 complex 是否配置了不同候选模型；
- 候选模型名称是否与 AI 网关路由完全一致；
- 请求是否超过最大请求字符数，从而直接进入 complex；
- 两组定义和样例是否边界模糊或互相冲突；
- 路由模型是否调用失败，导致使用默认路由。

### 路由试跑正常，真实请求却没有分流

路由试跑使用的是弹窗中的候选模型。真实请求的候选模型来自 AI 网关路由，请检查目标路由是否已经启用外部路由、Router URL 是否可达，以及路由模型列表是否与智能体映射一致。

### AI 规范并扩写后为什么没有生效

扩写结果只会应用到本地编辑表单。点击 **应用到表单** 后，还需要点击 **保存** 才会更新智能体。

### 删除并重建后 AI 网关持续回退

新智能体的 ID 已变化，而 AI 网关仍在访问旧 Router URL。编辑对应路由规则并替换为新智能体地址。
